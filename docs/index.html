soft-task

Skill / CLI для AI-збірки в існуючому репо: бриф або тікет → маніфест вимог → план → виконавці Softoria-HD → рев’ю → перевірка за брифом. Оркестратор — агент сесії (Cursor / OpenCode / Claude Code / Codex).

Огляд ролей

РольХтоЩо робить
Orchestrator Сесія, де викликали /soft-task Читає фази, st.py, запускає виконавців. Код додатку не пише.
Executor Softoria-HD (default) Один тікет = один процес opencode run --standalone.
Reviewer Softoria-HD або harness Точкове / гілкове рев’ю. harness = субагент середовища.
Vision Softoria-SD Текстова спека з макетів і перевірка скрінів (see.sh).

Етапи

  1. preflight — harness, .soft-task/config.json, дашборд (python -m http.server).
  2. manifest — бриф → пронумеровані вимоги (секрети ред’юсяться).
  3. briefing — закрити відкриті розвилки (залежить від mode).
  4. spec — spec.md, interfaces.md, notes.md.
  5. plan — тікети з зонами/хвилями; G3 = st.py check-plan.
  6. build — Softoria-HD; до 3 паралельно; зони без перетину.
  7. review — рев’ю змін.
  8. final — G4: перевірка лише за брифом (без спеки); smoke / скріни за потреби.

Режими: full · semi (default) · interview · manual. Depth: strict · normal · deep · task.

Що з’являється в репо

  • Код по тікетах + окремий коміт на тікет (після scoped-тестів).
  • Артефакти в .soft-task/: бриф, manifest, spec, interfaces, tickets, state.
  • Рев’ю (Softoria-HD або harness-субагент).
  • Тести: команди з тікета; stack detector — dotnet / Pest / npm / pytest / go.
  • Дашборд: http://127.0.0.1:<port>/dashboard.html (EN / UK / RU).

Встановлення

Node 18+, OpenCode, SOFTORIA_API_KEY, корпоративний VPN для Softoria API.

npx github:oleksandr-kupenko/soft-task install --harness all --yes
export SOFTORIA_API_KEY="…"

# у агенті:
/soft-task task <текст тікета або шлях до брифу>

FAQ

Хто виступає оркестратором?

Агент і модель у сесії, де викликали /soft-task. Диспетчер, не автор коду додатку.

Сервер дашборда піднімається сам?

Так. st.py init стартує http.server і відкриває dashboard.html.

Як змінити виконавців?

.soft-task/config.json: engines.executor (softoria-hd), engines.reviewer (softoria-hd | harness), engines.vision (softoria-sd). Можна назвати оверрайд у чаті на preflight.

Executor = модель Codex / Cursor?

Для рев’юера — engines.reviewer: "harness". Окремого executor-двигуна під Codex немає; тікети йдуть у Softoria через run.sh.

Як запускається Softoria-HD?

engines/softoria-hd/run.sh → opencode run --auto --standalone --model softoria/Softoria-HD#max.

VPN?

Без корпоративного VPN Softoria API зависає або віддає 5xx. Спочатку VPN.

Секрети?

У репо не комітяться. У промпт — імена змінних; значення в env / локальному .env.
